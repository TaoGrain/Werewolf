## 结论

真实对局成功完成。系统使用 MiniMax M3 且关闭思考模式，从身份分配连续运行至 `FINISHED`，没有注入行动、跳过阶段或替 Agent 决策。

游戏在第 2 夜结算后结束，狼人阵营获胜。结束时存活狼人 2 人、存活好人 2 人，符合默认规则 `wolves_win_at_parity=true`。

关闭思考模式实际生效：发送前真实探针捕获到 `thinking.type=disabled`；完整对局 29 次 LLM 调用的 reasoning Token 总数为 0，响应中没有独立思考文本，也没有 `<think>` 或 `<analysis>` 标签。

真实探针使用与完整对局相同的 `MiniMaxProvider` 和 Endpoint，在 `_post` 发送前捕获脱敏参数；探针本身不记录 API Key。探针返回同样没有思考文本或 reasoning Token。

完整对局运行时，持久化安全过滤器会删除请求快照中的 `thinking` 键，因此本轮数据库不能直接反查该控制键，旧版赛后脚本据此产生了误报。现已增加非敏感的 `thinking_mode` 审计字段，后续对局可以直接从持久化快照核验；这不改变本轮实际 HTTP 请求及其零 reasoning 结果。

## 模型表现分析

### 表现较好的部分

1. 所有最终行动都满足合法目标约束，游戏状态机顺利运行至终局。
2. 狼人能够在意见不一致时交流并收敛到统一目标，白天又成功协作放逐平民。
3. 预言家两次查验都命中狼人，信息选择本身非常有效。
4. 女巫能正确理解首夜自救规则和解药状态，没有提交非法用药行动。
5. 六个 Agent 会话隔离检查通过：29 个请求视图全部对应正确玩家，共识别出 6 个独立会话，没有发现全量身份或夜间状态泄露。
6. API Key 材料和内部思考内容的持久化检查通过。

### 主要问题

1. **预言家策略过于保守。** 5 号首夜已经查到 1 号是狼人，却在第一天隐藏身份并弃票；第二夜虽然又查中 6 号，但游戏在其公开信息前已经结束。高质量查验没有转化为阵营收益，是好人失败的核心原因。
2. **女巫过早公开身份。** 2 号首日直接公布女巫身份、解药已用和毒药仍在，为狼人后续避开或操纵女巫提供了信息。
3. **女巫第二夜过度保守。** 3 号遗言已经指出 1、6 号配合嫌疑，但女巫仍选择不使用毒药；在 6 人局人数临界点，这一选择直接保留了双狼存活。
4. **存在状态理解错误。** 1 号在第一天首轮发言中错误声称“2 号林雾走了”，但实际首夜无人死亡，2 号仍然存活。后续玩家发言纠正了这一错误，但说明模型对玩家视图中的存活信息仍可能读取不稳。
5. **行动与理由语义不一致。** 1 号最终投票目标是 3 号，但其公开理由主要在论证 5 号可疑。当前 Schema 能验证目标是否合法，却不能验证理由是否支持该目标。
6. **最终回答偏长。** 关闭思考消除了 reasoning Token，却没有自动减少业务字段中的长篇理由。长发言进入后续会话历史，使本轮输入 Token 达到 297,646；关闭思考不等于整体 Token 成本一定下降。

## 与此前真实运行的参考对比

2026-07-21 的真实 MiniMax 完整复测记录了 28 次调用、平均延迟 19,839.14 ms、总 Token 143,893。本轮关闭思考后平均延迟降至 10,597.66 ms，约下降 46.6%，且未出现 `finish_reason=length`。

但本轮总 Token 增至 307,167，主要来自更长的最终业务文本及其在多轮历史中的重复输入。两局虽然使用相同随机种子，但模型输出和行动路径具有随机性，不能视为严格 A/B 实验；可以确认的是 reasoning Token 已从非零降为 0，延迟显著下降，而总成本仍取决于最终回答长度和历史管理策略。

## 建议

1. 保持 MiniMax M3 请求中的 `thinking.type=disabled`，并继续持久化 `thinking_mode` 供审计。
2. 将 `public_reason`、`private_reason`、`private_strategy` 和狼人讨论的提示长度进一步压缩，例如明确要求 100～300 字。
3. 增加投票目标与公开理由的一致性校验，发现理由主要指向其他玩家时触发修复。
4. 在玩家视图或提示中增加醒目的“当前存活玩家列表”和“昨夜实际死亡列表”，降低把刀口误认为死亡结果的概率。
5. 为预言家、女巫增加人数临界点策略提示，避免在 6 人局中因过度保守错过唯一行动窗口。
6. 对历史消息做摘要或裁剪，避免长篇业务理由在后续请求中反复计入输入 Token。
